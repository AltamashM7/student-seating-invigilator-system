# First Evaluation Scope - S1 to S4

## S1
- Requirements and user stories
- Seating/invigilation constraint rules v0
- Repository, database and Servlet project setup
- ER diagram and authentication approach
- Design system and three dashboard wireframes
- Master test plan, severity levels and test-case format

## S2
- Password policy and account validation
- Users, admin, student and faculty data tables
- Register, login, logout and reset-password endpoints
- Login/reset/admin account screens
- Session and role access checks

## S3
- Room, seat and course data models
- Automatic seat generation
- Course CRUD
- Student/enrollment CSV import
- Duplicate and invalid-row reporting

## S4
- Exam session model and state workflow
- Exam CRUD
- Room-level and student-level timetable conflict detection
- Public timetable list/calendar view
- Inline conflict warnings in the admin exam form

Seating allocation and invigilator assignment are intentionally not implemented in this evaluation build because they begin after S4 in the master sprint plan.
